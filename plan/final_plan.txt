1. PROBLEM AND SCORING
=====================================================================
Task: for every Source 1 (S1) record, output all Source 2 (S2) and
Source 3 (S3) records that describe the same real-world business.
S1 is deduplicated. An S1 entity can match zero, one or many records.

Data: TSV files, columns entity_id, business_name, business_address,
country. Train covers US and India. Test adds France, which never
appears in training. The full test set is about 1.7M records.

Metric: F0.5 per S1 entity, then macro-averaged over ALL S1 entities.
  - truth empty, prediction empty          -> 1.0
  - truth empty, prediction non-empty      -> 0.0
  - truth non-empty, prediction empty      -> 0.0
  - otherwise F0.5 = 1.25PR / (0.25P + R)
Precision counts twice as much as recall. Singletons are worth a full
point each when we correctly predict an empty list.

Outputs (both tab-separated, UTF-8):
  matching_results.tsv   source1_entity_id | matched_entity_ids
  candidate_pairs.tsv    source1_entity_id | candidate_entity_ids
One row per test S1. Empty lists allowed. S2-/S3- IDs only. No
duplicates. Matches must be a subset of candidates. candidate_pairs
is the exact set the model scores, not an early blocking pass.

=====================================================================
2. KEY DESIGN DECISIONS
=====================================================================
D1  Blocking sets the recall ceiling. We measure blocking recall on
    full training data before building on top of it.
D2  We optimise the per-S1 decision directly (which subset, or none),
    not pairwise accuracy.
D3  A dedicated "empty list" gate captures singleton points.
D4  One-owner rule: since S1 is deduplicated, each S2/S3 record should
    belong to at most one S1. Verified in EDA (E3). If it holds, each
    S2/S3 record goes only to its best-scoring S1.
D5  Group context features (rank among an S1's candidates, gap to the
    best, reverse rank of the S1 among all S1s for that record) carry
    most of the signal in entity resolution.
D6  France is unseen. All features are country-agnostic similarity
    scores, ratios and flags. No country identity feature anywhere.
    Generalisation is tested with leave-one-country-out (LOCO).
D7  [Mentor 1] Global validation. OOF predictions for ALL train S1,
    then one-owner rule and threshold tuning on the whole training set
    at once, so every record competes with all its real rivals.
    Reverse features use blocking scores over all S1, never labels.
D8  [Mentor 2] Country-only blocking is used only if EDA (E5) shows
    true pairs share a country label about 100% of the time.
    Otherwise a cross-country fallback pass is added.
D9  [Mentor 3] Postal-like tokens = every standalone 5-6 digit number
    in any address, for every country. No `if country == ...`.
D10 [Mentor 4] French rules come from token frequencies in unlabeled
    test France records (provided data). Small dictionary, documented
    as domain rules. No hand-labelling of test records.
D11 TF-IDF vocabularies and IDF weights are fitted per split on that
    split's own S1+S2+S3 records (provided data, unsupervised).
    Documented as transductive preprocessing.

=====================================================================
- No external APIs, geocoding, business registries or internet
  lookups anywhere in src/. The pipeline never calls Claude or any
  hosted model. Claude Code is only a development tool.
- Every model in the final pipeline: MIT or Apache 2.0, at most 8B
  parameters. [Mentor 5] Check the model card before using any
  pretrained model. Record name, license and parameter count.
- Allowed core libraries: pandas, pyarrow, numpy, scipy, scikit-learn
  (BSD), rapidfuzz (MIT), lightgbm (MIT), pytest. Any new dependency
  needs the lead's approval and a license check.

  stage. No filtering, hard-coding or one-hot of countries.
- [Mentor 6] Everything reproduces from src/ via one command. CLAUDE.md
  and the Colab notebook may stay in the repo but are not needed to
  reproduce.

5. COMPUTE AND ENVIRONMENT
=====================================================================
Machines
- Laptops (MacBook Air, Windows): development on the dev sample only.
- Google Colab: the canonical machine for all full-data runs.
- Kaggle notebook (about 30 GB RAM): backup for memory-heavy runs.
  Data uploaded as a PRIVATE Kaggle dataset only.
- Colab Pro High-RAM is optional, not required.

Memory design (target: whole pipeline under 12 GB)
- Process one country group at a time (plus the fallback pass if
  needed).
- String IDs mapped to integer indices internally, converted back only
  when writing TSVs.
- TF-IDF top-K by chunked sparse multiplication (5k-20k S1 rows per
  chunk), float32. Never a full similarity matrix.
- Features computed in chunks and written as parquet parts.
- Load only the needed parquet columns. del + gc.collect() between
  stages.
- If memory runs out: smaller chunks first, then smaller K.

Colab reliability
- Every stage writes to Google Drive and is skipped if its output
  already exists (--force to rerun).
- The notebook only mounts Drive, clones the repo, installs
  requirements and calls run_pipeline.py. No logic in the notebook.
- Runtime and peak RAM logged per stage.

Cross-platform rules
- Same Python version as Colab for everyone (check `python --version`
  on Colab, pin it in the README).
- pathlib for all paths. No shell-only commands in Python.
- multiprocessing only under if __name__ == "__main__".
- Mac: brew install libomp before installing LightGBM.
- encoding="utf-8" on every open. "\n" line endings on write.

Dev sample (built by Member 1 in Phase 0)
- Fixed seed. About 10% of train S1, stratified by country x singleton
  flag, all their true matches, plus random other S2/S3 records as
  distractors.
- Debugging only. The sample has fewer distractors than real data, so
  it overstates precision. Scores and thresholds come only from full
  data.

TSV reading (all code goes through io_utils.read_source)
  sep="\t", dtype=str, keep_default_na=False, na_filter=False,
  quoting=csv.QUOTE_NONE, encoding="utf-8"
  Then assert row count = file line count - 1.
  (QUOTE_NONE stops a stray " from swallowing lines. keep_default_na
  stops a business named "NA" or an empty match list from becoming
  NaN.)

Data contracts (parquet, {split} = train or test)
- records_{split}.parquet
  entity_id, source (S1/S2/S3 from prefix), country, name_raw,
  addr_raw, name_norm, name_core (legal suffix removed), legal_suffix,
  name_acronym, addr_norm, postal_tokens (list), num_tokens (list),
  landmark_flag, name_empty, addr_empty
- candidates_{split}.parquet
  s1_id, cand_id, cand_source, country_match (bool agreement flag,
  not a country identity), pass_A_score, pass_A_rank, pass_B_score,
  pass_B_rank, pass_C_score, pass_C_rank, pass_F_score, pass_F_rank,
  n_passes, best_block_score, rev_n_s1, rev_rank, rev_gap
- features_{split}/part-*.parquet
  s1_id, cand_id, feature columns (float32), label (train only:
  1 if cand_id is in the S1's ground-truth list)
- oof_train.parquet: s1_id, cand_id, fold, prob, label
- pred_test.parquet: s1_id, cand_id, prob
- decision_config.json: t, t_empty, one_owner, optional per-source
  thresholds. Tuned on train, applied unchanged to test.
Nobody changes a contract without telling the lead.

Runner
  python -m src.run_pipeline --stage {prep,block,feat,train,predict,
    decide,write,all} --split {train,test} --data-dir <path>
    --out-dir <path> [--force] [--dev-sample]

Git

- Branches: feat/<module>-<desc>, fix/<module>-<desc>.
- PR checklist: runs on dev sample, tests pass, metric impact stated.
- Commit messages: <module>: <what changed> (e.g. "blocking: add

=====================================================================
7. SOLUTION ARCHITECTURE
=====================================================================
Stage 0 — Prep and normalisation (normalize.py)
 Name: lowercase, NFKD accent strip, & -> and, punctuation -> space,
 whitespace collapse, legal suffix extracted into its own column,
 abbreviation expansion, acronym (first letters of core tokens).
 Address: abbreviation expansion, postal-like tokens (every standalone
 5-6 digit number), all numeric tokens, landmark flag (near / opp /
 behind / beside), token set.
 Dictionaries are Python dicts in normalize.py. Every entry traces to
 EDA evidence.

Stage 1 — Blocking (blocking.py)
 Pass A: char 3-gram TF-IDF on name_norm, top-K per S1 within the
         country group.
 Pass B: TF-IDF on name + address, top-K.
 Pass C: records sharing a postal-like token, kept if name TF-IDF
         cosine > a low bar (e.g. 0.2), top-K.
 Pass F: cross-country fallback, name only, small K (only if E5
         requires it).
 Pass D: sentence-embedding ANN (stretch, Section 11).
 Union all passes, keep per-pass score and rank, n_passes. Cap total
 candidates per S1 (starting point 50) by best score.
 Reverse features over ALL S1: rev_n_s1 (how many S1s got this record
 as a candidate), rev_rank (this S1's rank among them), rev_gap
 (score gap to that record's best S1).
 Pair budget: (test S1 count) x (avg candidates per S1) must fit the
 12 GB chunked feature stage.

Stage 2 — Features (features.py)
 Name: ratio, token_set, token_sort, partial, Jaro-Winkler, normalised
 Levenshtein on name_norm and name_core; char and word TF-IDF cosine;
 IDF-weighted token overlap; rare shared token flag; acronym match
 (both directions); legal suffix agree / conflict / missing; length
 ratio; first-token match; digit-token agreement.
 Address: postal-like token equal / conflict / one missing; house
 number agreement; token Jaccard; TF-IDF cosine; landmark flags;
 missing-field flags.
 Group context: rank within the S1, gap to top score, candidate count,
 z-score within the S1.
 Blocking: per-pass scores and ranks, n_passes, reverse features,
 country_match.
 Source flag (S2 vs S3).
 NO country identity features.

Stage 3 — Model (model.py)
 LightGBM binary classifier. GroupKFold(5) by s1_id over all train S1.
 Early stopping, deterministic=True, fixed seed and num_threads.
 Saves OOF predictions for every train pair, 5 fold models, gain
 feature importance. Test probability = mean of the 5 fold models.

Stage 4 — Decision layer (decide.py)
 1. One-owner rule (if E3 supports it and it validates better): each
    S2/S3 record kept only for its highest-probability S1, across the
    whole split.
 2. Per S1: keep candidates with p >= t. Empty list if max p < t_empty.
 3. t and t_empty (optional per-source thresholds) tuned by grid
    search on full train OOF for macro F0.5. Saved to
    decision_config.json and applied unchanged to test.

Stage 5 — Output
 Write both TSVs via io_utils. Run the official validator every time.

8. VALIDATION PROTOCOL
=====================================================================
- Scorer must reproduce the README example (0.714) and pass the edge-
  case unit tests before any result is trusted.
- Blocking is unsupervised and runs on the full train split (all S1
  against the full S2/S3 pool).
- Model: OOF predictions for ALL train S1 via GroupKFold(5) by S1.
- Decision layer: applied to all train OOF at once [Mentor 1].
- Every experiment reports: pair recall, % S1 fully covered, avg
  candidates per S1, macro F0.5 overall / singleton / non-singleton /
  per country, LOCO score.
- LOCO: train on US -> score India; train on India -> score US. This
  is our proxy for France.
- Accept a change only if global macro F0.5 improves by >= 0.002 and
  LOCO drops by no more than 0.005.
- Compare train vs test distributions (candidates per S1, max
  probability, predicted-empty rate) to catch density shift.

11. ERROR ANALYSIS LOOP AND IMPROVEMENT PRIORITIES
=====================================================================
Loop
 1. From global OOF decisions, bucket errors:
    B1 false merge on a singleton (costs 1.0)
    B2 wrong extra match on a matched S1 (lowers precision)
    B3 miss: true match not in candidates (blocking)
    B4 miss: model or threshold rejected it
 2. Report each bucket as "F0.5 points lost".
 3. Pull 25 examples from the biggest bucket, tag causes.
 4. Fix the most common cause.
 5. Re-run on full train. Accept per Section 8, otherwise revert.
 6. Log it (below).

Experiment log (shared sheet), one row per experiment:
 id | owner | change | pair recall | avg cands/S1 | F0.5 overall |
 singleton | non-singleton | US | India | LOCO | accepted Y/N | notes

Improvement priorities (in order)
 P1 Missing group-context or reverse features.
 P2 Cross-source support: an S3 candidate that strongly matches an S2
    candidate of the same S1.
 P3 Expected-F0.5 subset selection per S1.
 P4 Seed averaging (3 seeds) of LightGBM.
 P5 Pass D embeddings, only if B3 misses are mainly transliteration or
    word reordering. License check first. Colab GPU, float16
    embeddings saved to Drive.
 P6 Cross-encoder re-ranker for borderline pairs (default: skip).
